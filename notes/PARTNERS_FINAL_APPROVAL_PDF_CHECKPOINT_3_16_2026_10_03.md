## Owner-accepted outcome

The owner accepted the production workflow and final Objects geometry after
the PDF and Projects work was rebuilt on the confirmed transition baseline.

The accepted flow is:

1. File Review keeps Project, Partner, and Client as run-scoped editable draft
   metadata.
2. Continue to Objects runs Estimation and does not create permanent Partner,
   Client, or Project records.
3. Final Approval is enabled only after every Object is priced and approved.
4. Final Approval atomically creates or matches Organization roles and Project,
   then freezes an immutable Project Version snapshot.
5. The same action generates a deterministic Client Proposal PDF, stores it
   privately, and leaves the user on Objects.
6. The action changes to a pale green Approved state and the download row
   becomes visible below Installation.
7. Partners groups Project rows inside native expandable Partner rows. There
   are no nested Partner, Project, or Version pages in this MVP.

## Client Proposal contract

The PDF is generated by the server with PyMuPDF. It does not call Claude,
Haiku, OCR, or any other agent.

It contains:

- populated Company Contacts only;
- optional company logo;
- Project, Partner, and optional Client;
- Object name, quantity, sale price per unit, and sale-price total;
- Delivery and Installation;
- Project Price, VAT, and Project Total.

It never contains self cost. The output supports non-Latin project metadata.
The browser download name is `Project_Partner_YYYY-MM-DD.pdf`. Unsafe filename
characters are replaced while spaces and readable names are retained.
