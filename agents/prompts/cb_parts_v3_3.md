Calculate major furniture parts for ONE complete object using all supplied images, text and the saved Front/Planner scope. Output JSON only, in English. This is one Calculate call. No pricing, labor, fittings, material catalog selection, joinery or small clearances.

First understand the complete object and its physical bays across all views. The saved locators are fallible review boxes, not physical dimensions. Include every assigned front even when outside its block locator. Preserve every planned block/shared ID exactly once. Do not invent fronts for a block with no assigned front IDs. Reuse the saved front types; uncertain upstream classifications remain unverified.

For a straight rectangular carcass, return kind="carcass" and an ordered list of side-by-side bays. One bay is one vertical column: vertically stacked doors/drawers belong to the same bay; a door beside a drawer stack belongs to a DIFFERENT bay. A pair of side-by-side door leaves uses two bay widths, but this does not automatically require an internal wall. Assign every front ID of the block exactly once. Never put side-by-side fronts in one vertical stack.

Estimate bay widths using labelled span endpoints in the same orthographic view. Include ALL intervals inside the span, even ones belonging to neighbouring blocks, then allocate only this block's intervals. When proportions are unclear, equal subdivision is acceptable. Briefly state the source span, included intervals and approximate allocation in assumptions. Do not replace a usable drawing dimension with a generic module width. If no reliable span exists, explicitly describe the dimensional assumption. Do not return a separate carcass width: code sums bay widths, so two adjacent bays contribute both widths, whereas stacked fronts contribute one bay width.

Carcass code generates two outer sides, one full top, one full bottom and one back. It sizes top/bottom/back from the summed width. At each internal boundary adjacent to a drawer bay it generates exactly ONE shared mounting partition; stacked drawers do not add partitions. It generates each visible front using its bay width and your front height; each drawer adds two body sides, two ends and one bottom, using your body_height and depth=floor((carcass depth in mm-100)/100)*100, minimum 100 mm. Do not output these panels again. shelves is the number of assumed shelves inside each bay, zero if none; do not add shelves through a drawer stack. Ordinary panel thickness defaults to 17 mm when thickness_mm=null. A specific finished thickness overrides it; purchasing/lamination is deferred.

Return each front's height and body_height; body_height must be null for non-drawers. A drawer body can be lower than its facade. Sum stacked front heights within their carcass height, leaving room for appliance openings where shown. Estimate carcass height separately from plinths and worktop. If useful and unspecified, about 600 mm from worktop TOP to wall-cabinet UNDERSIDE is an assumption, not a printed dimension.

For worktops, decorative panels, supports, stepped or non-rectangular structures that cannot use the straight-carcass rules, return kind="explicit" with bounding size, assigned front_ids and explicit major part rows. Do not flatten a corner by adding perpendicular bay widths as one straight width. The explicit mode does NOT get automatic carcass panels or partitions; include its necessary parts. An L-shaped worktop uses non-overlapping rectangular arms covering the full base depth to the wall, counted once. Worktop finished thickness defaults to 30 mm. A free-standing side panel is not automatically a cabinet with a door.

All dimensions except thickness_mm use each block's declared unit (mm, cm or m). thickness_mm always uses mm. Assumed sizes stay approximate. Use only these two block shapes:
