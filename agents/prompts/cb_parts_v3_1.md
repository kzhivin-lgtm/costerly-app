CB Parts V3.1

Calculate coarse physical parts for ONE complete furniture object from all supplied images, source text and the saved assembly plan. This is one Calculate call, not a request for another analysis stage. Output JSON only, in English.

First understand the whole object across all views. Then estimate each planned block's width, carcass height, depth and its internal bays, and list its major parts. Use printed dimensions and relevant legends first, consistent visual proportions second, reasonable furniture construction assumptions last. Never omit a major part because its size is not labelled. Do not mistake a whole-object dimension for one bay. Saved boxes and counts can be wrong: use the complete images, including adjacent drawer fronts assigned to the block even if outside its box. Do not invent a door just because a block exists.

Width estimation: when a block or bay is not dimensioned, identify the endpoints of a labelled span in the same orthographic view and distribute that span across ALL visible intervals between those endpoints in proportion to their drawn widths, including intervals belonging to neighbouring blocks; then sum only the intervals belonging to this block. Use aligned views to check which physical intervals are included. Do not replace this evidence with a standard module width. Briefly state the span and estimated interval widths in the existing assumptions field; if the span cannot be reliably associated, label the width as an assumption instead of claiming a measured derivation.

Keep every planned B/S ID exactly once. A shared worktop is separate, counted once, covering the full supported base footprint back to the wall. For L-shaped tops list non-overlapping rectangular arms, not a full enclosing rectangle. For sloped or curved panels a coarse enclosing rectangle is acceptable, note this assumption. Ignore gaps, joints, machining, fittings, labor and prices.

Count carcass sides, shared internal partitions, tops/bottoms, shelves, backs, front panels, drawer body panels and other major physical panels/supports. Do not invent shelves inside drawer bays. Two adjacent doors do not automatically require a divider. A side-mounted drawer bay requires mounting walls on both sides: at its boundary with another bay count ONE shared vertical divider, unless already counted. Stacked drawers share these walls; do not add a partition per drawer. A bay bounded by both outer sides needs no extra partition.

Each conventional drawer: two body sides, two body end panels and one bottom, plus its separate visible front. Do not also count a complete drawer box. Size fronts to their own bays, not the whole block. Different drawer-front heights need separate rows. Ignore small thickness deductions for this coarse estimate. Use the literal string "drawer_depth" for the depth dimension of drawer sides and bottoms; code will calculate floor((block depth in mm - 100)/100)*100, minimum 100 mm. End panels use the drawer bay width. Assume a plausible body height where hidden, not automatically the full facade height.

Ordinary panels default to 17 mm, worktops to 30 mm finished thickness. Return null thickness_mm to request that default; return a number only for a specific source/context thickness. This does not select a material or stock construction. A 40 mm finished panel may later require two 20 mm panels, do not resolve purchasing here. Small clearances are ignored, but plinths/supports and worktop thickness are not carcass height. If unspecified and compatible, assume about 600 mm from worktop TOP to wall-cabinet UNDERSIDE. Any resulting elevation is the worktop top, not automatically carcass height.

For each block explicitly declare unit: mm, cm or m. All numeric block sizes and part face dimensions use that unit; thickness_mm ALWAYS uses millimetres. Match the drawing's unit convention instead of copying centimetre labels into millimetre fields. block size is [width, carcass height, depth]; for a standalone shared panel use its bounding width/height/depth. Use one short assumptions string per block for uncertain geometry/construction and the basis of estimates. Mark approximate=true whenever a face dimension is inferred, proportional or assumed; false only when both face dimensions are directly supported. Group only identical name, size and thickness, otherwise separate rows.

Exact output shape (illustrative values only):
{"blocks":[{"id":"B01","unit":"cm","size":[120,80,60],"assumptions":"Bay widths estimated from aligned fronts; hidden back assumed full height.","parts":[{"name":"Carcass side wall","quantity":2,"role":"panel","size":[80,60],"thickness_mm":null,"approximate":true},{"name":"Drawer body side","quantity":6,"role":"panel","size":["drawer_depth",18],"thickness_mm":null,"approximate":true}]}]}

Allowed roles: panel, worktop, support. Positive integer quantities. Positive dimensions. No other fields, prose, totals or material catalogue choices. Return the actual complete object, not the illustrative example.
