# RFQ DETECTION REGISTRY VNEXT 3.15.8

Return only the locked commercial-object registry. The input contains full pages and a separate visual representation map. The visual map was prepared from full pages and enlarged regions, but is navigation evidence only. It is not an object set and does not decide product boundaries.

Decide commercial objects only from the full pages. First determine the complete fabricated products a contractor would quote. Then attach relevant `visual_group_ids` from the map to the product they represent. A visual group may be an overview, alternate view, elevation, section, detail, component, module, panel, door leaf or track. It must not become a commercial object merely because it appears separately in the map. A group that does not support a returned commercial object is not a reason to add, split or fail an object.

Merge visual groups only with positive evidence that they are representations of the same physical assembly: a shared distinctive silhouette and structure, an explicit view relation, a common object code, or a matching unique envelope and panel sequence. A shared page, room title, project, material palette, visual proximity, lack of object codes, or generic furniture scope is never merge evidence. A front and perspective of the same long cabinet are one object only when their distinctive structure and panel sequence match.

Different complete envelopes, functions, silhouettes, or construction systems are strong independent-product evidence even without an object code. For example, a vertical shelving unit, a track-supported door system, and a long storage console shown separately on one furniture sheet are three objects. Their repeated projections remain one object each. Never return a generic room-furniture assembly that absorbs such independent candidates.

An object is one physical product a custom-fabrication contractor would quote, fabricate, supply, install, replace, or price independently. Split only with strong independent-product evidence: separate envelope, function, code, quantity, responsibility, or independent fabrication and installation. A complete sliding or hinged door system with its own leaves, track and frame is an independent product when separately drawn, even when it shares a sheet with cabinetry or the same material palette. Never merge that door system into a cabinet, shelving, TV console or wall system merely because they are adjacent. Never create entries for views, components, panels, fronts, tracks, hardware, appliances, loose lighting, MEP, decor, renders or drawing pages.

A kitchen, integrated cabinet wall or shelving wall is one object. Its blocks, modules, panels, fronts, carcasses, profiles, hardware and assembly sheets are construction detail, not objects.

Several door leaves suspended from the same continuous track or guide are one Door system with quantity 1, unless the drawing explicitly establishes separate systems, tracks, deliveries or quote quantities. Leaf dimensions are construction detail, not the system quantity or external envelope. Record the shared track and leaves in `boundary_basis`.

Return schema JSON only. `object_id` is ordered `object-001`, `object-002`, and so on. `transport_label` is the exact object code when printed, otherwise `Object 1`, `Object 2`, and so on. `quantity` is the number of complete physical objects. `identity_pages` uses physical upload page numbers. `dossier_pages` is a compact set of 1-12 pages only for the next Detection stage. `visual_group_ids` must contain every map group represented by this one commercial object. `visual_identity` describes the complete silhouette and the specific full-page groups or views that prove it. `boundary_basis` records the factual reason it is one quote line and must not rely on a shared sheet or room alone. Do not extract dimensions, materials, pricing or names.

`page_coverage` is a compact complete ledger for every physical upload page, exactly once. For each page return `page_number`, `object_ids`, and `exclusion_code`. Put every commercial object that materially needs that page for materials, purchased components or fabrication work in `object_ids`; a page may support several objects. When `object_ids` is non-empty, set `exclusion_code` to `none`. When no object needs the page, set `object_ids` to `[]` and use exactly one code: `cover`, `blank`, `administrative`, `other_trade`, or `unrelated`. Do not write prose. This ledger, not a free page list, deterministically creates Estimation Evidence. For a kitchen include its relevant block, assembly, facade and specification pages, not only overview pages.
