# RFQ DETECTION REGISTRY VNEXT 3.15.8

Return only the locked commercial-object registry. The input contains full pages and labelled enlarged page regions. Use enlarged regions to identify separate drawing groups, then use the full pages to link only proven repeated views of the same physical product.

Start with coverage: every spatially separate, maximal complete product drawing group is a separate candidate. A candidate is maximal only when it depicts a self-contained commercial product, not a crop, an enlarged part, a detail, a component, or an overlapping sub-region of another product depiction. An independently drawn complete item has a presumption of being a separate commercial object. Before the final registry, account for every independent maximal candidate on every full page. Enlarged regions are inspection aids only and cannot create additional candidates. Each independent maximal candidate must map either to one returned object or, only with positive containment evidence, to a returned parent object.

Resolve nested or overlapping depictions before counting objects. When a smaller region is wholly or substantially inside a larger product depiction, or shows only its panel, section, cabinet bay, door leaf, track, shelf, hardware or another component, it belongs to that larger candidate and cannot become another object. This remains true even when the smaller view looks complete or is supplied as an enlarged region. Return it separately only with direct evidence of a separate commercial product, quote scope, code, quantity, delivery or installation.

First consolidate alternate views. Merge candidates only with positive evidence that they are representations of the same physical assembly: a shared distinctive silhouette and structure, an explicit view relation, a common object code, or a matching unique envelope and panel sequence. A front and perspective of the same long cabinet are one object only when their distinctive structure and panel sequence match.

Then apply containment. A candidate becomes a component of a kitchen, integrated cabinet wall, shelving wall, counter system, or other common assembly only when the source positively proves integration, for example an explicit assembly relation or common object code, a continuous shared carcass, worktop or structural frame, or mutually dependent modules in one continuous construction. A component may have a separate perspective, elevation, complete-looking enclosure or its own dimensions, but that alone never makes it a quote line.

A shared page, room title, project, material palette, visual proximity, lack of object codes, generic furniture scope, or a coherent design style is never merge or containment evidence. Without positive duplicate-view or containment evidence, different complete envelopes, functions, silhouettes, or construction systems remain separate objects. For example, a vertical shelving unit, a track-supported door system, and a long storage console shown separately on one furniture sheet are three objects. Their repeated projections remain one object each. Never return a generic room-furniture assembly that absorbs such independent candidates.

An object is one physical product a custom-fabrication contractor would quote, fabricate, supply, install, replace, or price independently. Split only with strong independent-product evidence: separate envelope, function, code, quantity, responsibility, or independent fabrication and installation. A complete sliding or hinged door system with its own leaves, track and frame is an independent product when separately drawn, even when it shares a sheet with cabinetry or the same material palette. Never merge that door system into a cabinet, shelving, TV console or wall system merely because they are adjacent. Never create entries for views, components, panels, fronts, tracks, hardware, appliances, loose lighting, MEP, decor, renders or drawing pages.

A kitchen, integrated cabinet wall or shelving wall is one object. Its blocks, modules, panels, fronts, carcasses, profiles, hardware and assembly sheets are construction detail, not objects.

Several door leaves suspended from the same continuous track or guide are one Door system with quantity 1, unless the drawing explicitly establishes separate systems, tracks, deliveries or quote quantities. Leaf dimensions are construction detail, not the system quantity or external envelope. Record the shared track and leaves in `boundary_basis`.

Return schema JSON only. `object_id` is ordered `object-001`, `object-002`, and so on. `transport_label` is the exact object code when printed, otherwise `Object 1`, `Object 2`, and so on. `quantity` is the number of complete physical objects. `identity_pages` uses physical upload page numbers. `dossier_pages` is a compact set of 1-12 pages only for the next Detection stage. `estimation_evidence_pages` is every physical page materially needed to calculate this object's materials, purchased components or fabrication work. For a kitchen include all relevant block and assembly pages, not only overview pages. `visual_identity` describes the complete silhouette and the specific full-page groups or views that prove it. `boundary_basis` records the factual reason it is one quote line and must not rely on a shared sheet or room alone. Do not extract dimensions, materials, pricing or names.
